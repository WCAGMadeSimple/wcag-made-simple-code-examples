Not all alt text implementations are the same

Read this page with a screen reader of your choice to hear how these different implementations of alt text are announced.

You can pair this example with the Accessibility Tree in Firefox. There you can see which images surface in the accessibility tree versus which get announced by screen readers.

Missing alt attribute

When no alt attribute is present, a screen reader may attempt to announce whatever it can pick up from the image.

This could be things like height and width attributes, or file name values.

Empty alt text

The primary use case for empty alt text is for decorative images. While semantically correct, a screen reader may still announce something if not paired with additional attributes.

Empty alt text with aria hidden

aria-hidden="true" is effective at suppressing announcements in most screen readers.

Empty alt text with role none

role="none", which is an alias for the older role="presentation", is used to indicate that an element is used for presentational purposes only.

In testing, VoiceOver required role="none" to suppress the announcement. aria-hidden="true" alone was not sufficient.

Combine all three for the highest level of cross compatibility

For maximum compatibility across all screen readers, combine all three attributes.
